Bugs and issues
The biggest UX bug is that clicking "Scan URL" while the input still shows the placeholder (https://example.com) silently fails — the form appears to submit, clears, but nothing happens. The input value typed via normal UX seems to occasionally not register on first click either (I had to re-enter and re-click for Airbnb). You should either disable the button until a valid URL is present, or auto-focus/select-all on click.
The "Schema Detected" section uses opacity-50 to mark undetected schema types, which is visually subtle and fails accessibility checks — a user skimming the report would reasonably think every schema type was detected on every site. Add an explicit checkmark/X icon or split into two lists ("Detected" / "Missing") rather than relying on opacity alone. Screen readers will read "Organization, LocalBusiness, Article..." as if all were found.
Rate limit messaging ("Limit: 20 audits per hour per account") is shown but there's no visible counter of how many the user has used. When a user hits the limit, they'll only learn at submission time.
The blue "temporary development preview" banner dismisses on the dev URL but there's no way to return to the production aeoimprovement.com app with a signed-in session — the prod domain showed me a signup modal even though I was logged in on the dev preview. Session cookie scoping likely needs attention before public launch.
On Stripe, the report cited "1.64% of global GDP" as a fact from the page, but I'd recommend the tool clarify which extracted stats are direct quotes vs. paraphrased — for LLM-generated output this matters for user trust.
Improvements I'd prioritize
Add progress indication beyond the spinner — a step tracker ("Fetching page → Analyzing content → Checking crawlers → Computing scores") would massively improve the 20–30 second wait. Right now the user doesn't know if it's hung.
Let users re-run an audit from the results page (e.g., after they've implemented changes). Currently you have to go back home and re-type the URL.
The llms.txt recommendation appears aggressively — for Stripe, llms.txt was already found but the "Actionable Quick Wins" still sometimes reads like it might reappear. Double-check that satisfied checks don't resurface as recommendations.
Consider a comparative/historical view: if a user audits stripe.com monthly, show a delta graph. Right now "Your Recent Audits" shows duplicate entries (I saw shelving.com twice with the same score) with no diff.
Add CSV/JSON export alongside the PDF — agencies reselling this will want to pipe findings into their own dashboards.
The Brand Authority signal for NYTimes said "Article exists for 'The New York Times' but does not match the brand" because the detected brand was parsed as "Nytimes" from the domain. The brand-name extraction should normalize (title case, spaces) before Wikipedia matching, otherwise you'll miss entity matches for most multi-word brands.
The "Top recommendations" prose sometimes contradicts the structured recommendations below — Stripe's top rec #2 said "Stripe has only 1 question-style entry detected" while the lower section said the same thing but phrased slightly differently. Consolidate these so the executive summary and GEO recommendations list are clearly derived from the same signal set.
Finally, a small one: the AEO Score badge uses red even for a 54/100 which reads as "failing" — consider a red/yellow/green tiering (e.g., red <40, yellow 40–70, green >70) so users get an intuitive severity read.
